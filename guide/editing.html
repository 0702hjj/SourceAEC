编辑与版本 ​

平台里所有修改都是改构建脚本。IFC 和 DXF 永远是脚本跑出来的产物，所以任何一次保存，背后一定是一次脚本变更。

本页讲设计师视角的模型与操作。端点契约见 IFC 编辑 API，界面控件见界面使用，AI 侧接入见 AI 接入。

核心概念：script-as-source ​

plan / design 草稿（可选，AI 构思辅助，不落版本）
   → 构建脚本 v{n}.py（唯一事实源：PARAMS + build()）
   → 沙箱执行 → IFC / DXF v{n}（派生物，可随脚本重建）

三件事由此成立：

  • 模型等于脚本。每个大版本保留完整的 scripts/v{n}.py 和定位信息 v{n}.map.json，产物文件只留最新一份；历史版本需要对比或下载时，从对应脚本重建。
  • 选中即定位。点构件能跳到生成它的那一行脚本，改完先试运行看效果，满意再保存成大版本。
  • 对比不做几何。分两层：脚本层面的文本 diff，加上构件属性层面的语义 diff。改几何就是改脚本，所以不需要几何对比。

design JSON 只是个例外说明：它指 AI 起草阶段的草稿，不是模型的完整表示，不进版本、不参与 diff。与 IFC 一一对应的只有构建脚本，交付物永远是脚本。

模型的两种形态 ​

  • script-backed：模型有构建脚本，具备完整编辑能力——定位、参数表单、脚本编辑器、暂存、版本。
  • plain：模型是外部上传的，没有脚本，只能查看和审查。让 AI 把它复现成脚本之后就变成 script-backed，见文末 bootstrap。

选中构件，定位脚本 ​

属性面板是只读的，要修改先选中构件，点定位脚本按钮：

  1. 按 IFC GlobalId 查（DXF 侧按实体 key 查）。
  2. 命中后自动切到 Design 面板的脚本编辑器，光标落在生成这个构件的那一行并高亮。
  3. 查不到就保持只读。如果暂存脚本和定位信息对不上，会提示先运行一次脚本再定位。

两种改法 ​

Design 面板有两种模式：参数表单和脚本编辑器。定位结果里的 origin 标签决定用哪种：

  • origin 是 params：构件参数来自脚本头部的 PARAMS 块。在参数表单里改对应键的值，提交即可。
  • origin 是 literal：参数是写死在调用行里的字面量。直接在脚本编辑器里改这一行，或者让 AI 调定向改写接口由服务端精确重写这个标量，保留原有格式和注释。
  • origin 是 traced：参数是运行时算出来的，只能定位不能自动改写，请打开脚本编辑器手动改。

沙箱验证与暂存 ​

表单提交或脚本保存时，先做静态契约校验，不通过直接报 422，什么都不会被修改。通过后进入暂存区：最多保留 10 步，原子落盘，重启不丢，支持撤销和重做。

暂存之后有三个去向：

  • 放弃：丢弃整条暂存链，不产生任何版本。
  • 试运行：在沙箱里执行暂存脚本，预览产物，不产生版本。
  • 保存版本：执行脚本生成 IFC 或 DXF，固化为大版本 v{n+1}。

Design 面板在 xeokit、web-ifc、DXF 三条查看分支上完全一致，共用同一份数据和接口。

大版本与回滚 ​

大版本是用户或 AI 主动保存的检查点。脚本和定位 map 全量保留、成对快照，编号只增不改。产物文件只物化最新一份，历史版本 diff 或下载时从脚本重建，结果进缓存。

版本列表里可以对非当前版本回滚：恢复那版的脚本并重新执行。因为回滚走的是同一套链路，脚本和产物永远一致，不存在改了产物没改脚本的分叉。

AI 下次介入时拿到的输入是当前脚本加两层 diff 摘要，所以它的修改是增量式的，不是推倒重写。

版本对比 ​

工具栏的 Diff 按钮打开对比面板：

  1. 选 base 和 target。target 可以是某个版本，也可以是当前状态。
  2. 点对比。绿色是新增，黄色是修改，红色是删除。
  3. 点条目定位到构件；修改条目可以展开，看每个字段的旧值和新值。
  4. 点清除复位着色。

对比按确定性 GlobalId 或实体 key 对齐，IFC 和 DXF 两侧逻辑相同。对比分三个粒度：

层对象受众
脚本文本 diff 加 PARAMS 键级变更v{n-1}.py 对 v{n}.py，以及暂存步之间AI 的下一轮上下文；用户在脚本 diff 视图看
IFC 语义 diff，属性级 GlobalId 对齐两个版本的 IFC用户在 Diff 面板看
外部上传模型，按 GlobalId 做属性级对比无脚本时的对比对象用户

中途预览 ​

AI 或人在试运行成功后，保存版本之前就能看到中间结果：

  • DXF 和 web-ifc 分支画布直接刷新，代价低。
  • xeokit 分支重转 XKT 比较慢，画布左上角出现「AI 中间结果 · 点击预览」角标，点击才重载。

保存大版本后由提交完成事件驱动常规刷新。

bootstrap：把上传的 IFC 变成脚本 ​

有 AI 参与时，上传 IFC 的意图是让它照着做一份：

  1. 用户上传 IFC，此时是 plain 态，只能看。
  2. AI 通过 MCP server 读取模型，用 aiifc skill 编写复现脚本。
  3. 首次暂存时平台自动把上传原件保存为 bootstrap.ifc。脚本经沙箱验证后保存为大版本 v1，模型转为 script-backed。
  4. 首次保存的响应里有 alignment 计数，也就是原件和生成结果之间的差异摘要，用它判断复现是否走样；对齐计算失败不影响保存本身。
