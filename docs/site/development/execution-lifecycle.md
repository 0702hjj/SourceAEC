# 执行、并发与恢复

原生编辑、转换结果发布与模型状态更新在获取数据库连接前，共用按存储命名空间和
模型 ID 区分的进程内准入：每模型一个活动写入、最多 64 个等待者，取消后释放名额。
超出等待上限返回可重试错误，网关模型重试接口返回 429。
PostgreSQL 模型锁仍负责跨进程互斥；进程内准入不提供跨副本连接预算。
支持单个网关及遵守同一锁协议、共享投影目录和数据库命名空间的辅助运行时进程。
多个独立文件投影的网关副本、全局执行预算与持久任务续跑没有部署契约，不应据此启用。
`modelWaiting` 统计共同准入的等待者，`editModelWaiting` 保留原生编辑等待统计。

脚本、参数与版本列表 GET 使用 PostgreSQL 只读快照，不等待同模型几何执行，也不从
未提交的磁盘暂存投影读取。运行、保存、回滚与分支操作先以短只读快照捕获
执行身份，释放连接后准备环境并执行。发布时获取模型锁，重新校验暂存、产品、
版本、Git 分支、项目归属与输入；任何变化返回 409，调用方读取新状态后重试。
每进程最多三个完整构建生命周期，等待发布的结果也计入预算；满载返回 429。
源码历史比较也在快照关闭后执行旧脚本，不持连接等待几何。
已有产品的比较另有三个名额，不占几何构建预算；只有需要重放旧源码的比较才申请构建名额。
文件投影修改前记录路径 journal；进程重启时，以数据库已提交内容恢复被修改的
文件并删除未提交的新路径。恢复与正在发布投影的编辑事务互斥。

构建输入通过单条数据库查询读取模型的项目归属及该项目的 plans/skill-work 输入，
复用调用者的事务与连接。文件投影缺失或落后不会改变传入沙箱的输入字节；
其他事务尚未提交的项目归属和输入也不会被采集。仅允许的 JSON/Python/DXF 输入
参与构建，历史目录排除，单文件上限 64 MiB、合计 256 MiB。
输入与源码属于同一 repeatable-read 快照，执行期间不持数据库连接或模型锁。
同一次请求只执行一次用户脚本；不同保存请求仍重新执行，不假定用户脚本具有确定性。

写事务同时提交短期凭据；COMMIT 应答丢失时，在模型锁下查询凭据以识别已提交状态。
无法连库确认时报告提交结果未知并保留 journal，不自动重新执行。凭据保留至少十分钟，
后续写事务清理过期记录；长时间断连后客户端应重新读取业务状态。
诊断接口 `sourceaecStages` 提供准备、环境、执行、发布及模型等待的累计次数和纳秒，
这些聚合值不代表请求分位数。

## 资源边界

任务名额限制并发数量，不代表总内存配额。比较会读取两个完整产品，下载会持有
完整的已提交源；Go 堆之外还应考虑 Python/Node 原生内存与 PostgreSQL。
容量规划应使用实际模型大小、并发数与慢客户端测试，见[性能验证](/development/performance)。

## 当前恢复范围

数据库事务、提交凭据与投影 journal 保护已提交状态。它们不保存运行中的 Python
进程，也不提供持久工作流续跑。转换队列在进程内去重；预览可从已提交源重新生成。
客户端取消或进程退出后，不应假定未完成的脚本会自动重试。
