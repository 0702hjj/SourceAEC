# 模型存储

PostgreSQL 是业务持久化来源。磁盘目录是供转换器、Git 和沙箱使用的投影，
不要手工修改运行时 data 目录。通过 API 改变脚本、版本或项目状态。

Go 保存脚本、产品、元数据和暂存历史。保存版本时，脚本、产品、不可变历史引用、
版本号及暂存清理在同一事务中提交，不执行 Git 命令或重写全量 bundle。
执行失败保留当前状态；版本保存后不可变。源码 patch 是修改指令，完整快照是持久事实。
Go 编辑请求使用事务级模型锁，不依赖 Python 进程内缓存。

版本列表、保存编号与 Git 历史导入以数据库记录为准。首次编辑或列出旧模型版本时，
短写事务将旧 `versions` 产品文件迁入持久归档，再记录迁移完成标记；此后目录只是
投影，删除或添加临时目录文件不会改变版本。旧文件时间在可用时写入元数据；
无法恢复的旧时间保持空值。已有 journal 涉及的未提交路径会恢复并隔离，不作为历史版本导入。
升级时应停止旧写入进程，避免混用目录编号与数据库编号逻辑。

原生编辑使用类型化产物读写接口，共享私有 stdio 协议的事务与持久化规则，
大产品在进程内不再反复经过 JSON/base64 编解码。

运行时模型源码可以具有 `.py` 后缀；这是数据库和临时工作区里的用户数据，
不是仓库维护的业务源码。外部依赖环境也不进入版本控制。

部署需要 `VIEWER_PG_DSN`，可用 `VIEWER_STORAGE_NAMESPACE` 隔离业务空间。
测试应使用独立数据库。升级前备份数据库和运行时目录。

升级包含投影恢复协议及产物摘要列的初始化，应先停止旧版本写入进程，再启动
新版本。首次初始化会计算已有产物的摘要；没有 generation 清单的旧预览会重新转换。

旧 SQLite 数据的离线迁移命令仍在 `server/cmd/migrate-sqlite`，需要 CGO，
不包含在默认静态二进制发行包中。

## 旧脚本兼容

迁移不修改既有运行时数据。旧脚本和产品可继续读取；若旧脚本导入了已退役的
本仓画法库，重新运行前需要将模型源码改为外部 SDK，或由管理员提供兼容的
外部运行环境。移除旧 SDK 不代表历史脚本自动获得新的库接口。

## 存储职责

| 数据 | 权威来源 | 文件系统用途 |
| --- | --- | --- |
| 源码、产品、版本、输入、暂存 | PostgreSQL artifacts | 可恢复的工作区投影 |
| 源码历史与版本号 | versionstore 的不可变引用、head 和计数器 | 按需恢复源码投影 |
| Git 兼容历史与分支 | 历史 bundle 与已投影记录 | 按需 Git 工作区 |
| 预览 generation | 数据库清单与不可变文件 | 可重建显示缓存 |
| 工作流状态原语 | workflow 的定义、运行、尝试、租约和检查点引用 | 无执行器；尚无异步执行 API |
| 执行进程与队列 | 进程内状态 | 不提供持久续跑 |

Git 查询和分支操作按需将保存记录投影为真实提交，每个事务最多 32 条。
批次提交后取消可保留进度；失败不回滚已保存的产品。
单次投影准备最多运行 30 秒或 64 批，未完成返回 429；重试继续已提交进度。
来源和原始接受时间保存在历史记录，并带入 Git 提交。
查询状态时先捕获一致 bundle，释放连接后再运行显示命令。
分支切换/合并仍使用 Git 保留原有 DAG 和冲突规则，结果经过执行身份校验后才能发布。
新保存响应中的 `historyRevision` 是源码历史 ID；Git SHA 由 `/git` 查询提供。

旧模型首次执行初始化历史 head 和版本计数，保留旧 bundle 的提交与分支，编号包含旧标签。
这次导入可能需要 Git；新模型的正常保存不需要 Git。升级仍须停止旧写入进程，
旧版本不能与新版本混用，否则旧写入者不认识历史 head 和投影标记。
已有产品归档和 Git bundle 仍按原备份要求保留；历史引用不能脱离其归档文件恢复。
不要将产品语义 diff、源码修改或缓存复用视为同一种存储机制。
[执行与恢复](/development/execution-lifecycle)说明锁、快照和失败边界；
[预览与读取](/development/preview-storage)说明派生产物的生命周期。

## 工作流状态边界

`workflow` 是内部 PostgreSQL 状态原语，初始化时创建表，删除模型时在模型事务中
级联清理定义、运行和尝试。定义不可变，只保存摘要与模型内的内容寻址引用，不保存进程内存。
状态转换需要调用方事务；模型发布及工作流发布标记只有放在同一事务中才具备原子性。
租约使用数据库时间，旧尝试令牌、过期或取消的所有者不能继续写入。

每个阶段最多三次自动领取，确定失败可终止，显式恢复保留原定义和检查点。
重试带有限退避；内部空轮询仍可提交已耗尽尝试的清理。待处理运行最多 64 个，
合计输入及定义清单的逻辑字节最多 2 GiB；它不限制已完成历史、产物存储或总内存。
这是写入状态前的检查，调用方仍须在捕获大输入前另做资源预留。

这些原语不执行几何、不验证引用内容或环境文件，也不替代模型事务/提交凭据。
当前同步编辑与进程内转换队列没有通过它们调度；仍不能自动续跑中断的脚本。
