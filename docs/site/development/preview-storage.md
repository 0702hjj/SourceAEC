# 预览与产物读取

IFC 转换读取固定的已提交源和构建身份，完成时校验身份后发布。几何与 metadata
位于同一个不可变预览 generation；过期转换的成功或失败不能覆盖新源状态。
预览缓存丢失会重建；启动及成功转换后回收超过一小时且未被清单引用的 generation。
当前清单引用的 generation 始终保留，单组 XKT/metadata 合计最多 1 GiB。
读取在模型锁内打开文件描述符后释放连接，后续回收或删除不打断在途 Range 读取。
相同源的重复队列结果不会替换已有完整预览，也不会用迟到的失败覆盖 ready。
模型删除使用共同准入与数据库模型锁，一次删除源、构建、版本、仓库及清单；
删除后的旧执行返回冲突、旧转换结果被丢弃。遗留磁盘投影不能使已删除数据重新出现。
下载读取已提交源，DXF render 从已提交产品生成，不向客户端暴露未提交的投影。
下载使用 PostgreSQL repeatable-read 快照，以 1 MiB 分片导出私有文件，释放数据库连接后
再提供 Range 响应；不使用可变工作区中的源文件。临时文件打开后立即 unlink，
连接关闭或进程退出后由操作系统回收。每进程最多 8 个读取快照、合计 4 GiB 临时文件，
满载返回 429。该预算不包含 PostgreSQL 为导出物化的内存与临时文件。
磁盘快照避免慢客户端长期持有整份 Go 切片，但增加导出与磁盘开销；应在部署环境测量。
磁盘清理是可重试的派生操作；转换后的自动清理失败通过 `previewGCFailed` 计数，
不将已提交版本回滚。当前策略不提供跨模型的全局磁盘配额。

转换入队等待模型准入时不持有队列互斥锁；发送前重新检查关闭状态与容量。
模型准入满时，仍可由有界转换队列接收任务，worker 重试发布已有结果，避免重复转换。


原始源与版本属于持久业务数据，预览是可重建缓存。两者的删除、回收和恢复规则
不能混用，见[模型存储](/development/model-storage)及[执行生命周期](/development/execution-lifecycle)。
