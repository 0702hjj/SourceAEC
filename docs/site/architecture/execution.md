# 执行、并发与恢复

原生编辑、转换结果发布与模型状态更新在获取数据库连接前，共用按存储命名空间和
模型 ID 区分的进程内准入：每模型一个活动写入、最多 64 个等待者，取消后释放名额。
超出等待上限返回可重试错误，网关模型重试接口返回 429。
PostgreSQL 模型锁仍负责跨进程互斥；进程内准入不提供跨副本连接预算。
支持单个网关及遵守同一锁协议、共享投影目录和数据库命名空间的辅助运行时进程。
多个独立文件投影的网关副本与全局执行预算没有部署契约。单网关可显式使用
[持久工作流](/reference/workflows)恢复脚本任务。
`modelWaiting` 统计共同准入的等待者，`editModelWaiting` 保留原生编辑等待统计。

脚本、参数与版本列表 GET 使用 PostgreSQL 只读快照，不等待同模型几何执行，也不从
未提交的磁盘暂存投影读取。运行、保存、回滚与分支操作先以短只读快照捕获
执行身份，释放连接后准备环境并执行。发布时获取模型锁，重新校验暂存、产品、
版本、Git 分支、项目归属与输入；任何变化返回 409，调用方读取新状态后重试。
捕获、执行和发布是独立的类型化边界；捕获结果绑定存储、模型及格式，持有固定请求、
源码与输入副本，不持有 SQL 事务。执行器取得独立输入 map，不能改写构建清单中的固定输入。
发布只消费已完成结果，重新检查身份后提交，不再执行一次几何。这里的捕获结果仍是内存状态。
每进程最多三个完整构建生命周期，等待发布的结果也计入预算；满载返回 429。
源码历史比较也在快照关闭后执行旧脚本，不持连接等待几何。
已有产品的比较另有三个名额及合计 512 MiB 原始输入预算，在读取前按同一快照的
内容大小预留；失败或取消释放。旧源码重放按单产品最大 256 MiB 预留，并申请构建名额。
该字节预算不包含格式解析结构与外部几何进程，不等于进程 RSS 上限。
文件投影修改前记录路径 journal；进程重启时，以数据库已提交内容恢复被修改的
文件并删除未提交的新路径。恢复与正在发布投影的编辑事务互斥。

构建输入通过单条数据库查询读取模型的项目归属及该项目的 plans/skill-work 输入，
复用调用者的事务与连接。文件投影缺失或落后不会改变传入沙箱的输入字节；
其他事务尚未提交的项目归属和输入也不会被采集。仅允许的 JSON/Python/DXF 输入
参与构建，历史目录排除，单文件上限 64 MiB、合计 256 MiB。
输入与源码属于同一 repeatable-read 快照，执行期间不持数据库连接或模型锁。
同一次请求只执行一次用户脚本；不同保存请求仍重新执行，不假定用户脚本具有确定性。

写事务同时提交短期凭据；COMMIT 应答丢失时，在模型锁下查询凭据以识别已提交状态。
无法连库确认时报告提交结果未知并保留 journal，不自动重新执行。凭据保留至少十分钟，
后续写事务清理过期记录；长时间断连后客户端应重新读取业务状态。
诊断接口 `sourceaecStages` 提供准备、环境、执行、发布及模型等待的累计次数和纳秒，
这些聚合值不代表请求分位数。

## 资源边界

源码映射独立于几何产物，原始及规范化 JSON 各最多 16 MiB、262144 个 JSON token
（含键名与容器分隔符）、32 层对象/数组嵌套。超过预算返回 422，不发布候选产物。
沙箱映射文件在读取前检查大小；读取已保存映射时在同一数据库快照内先检查大小，
再做结构预算检查。字节与结构预算限制解析对象数量，不构成进程 RSS 保证。

格式检查和比较也设结构预算，输入最多 256 MiB。IFC STEP 最多一百万条记录、
合计两百万个直接字段、128 层聚合嵌套；记录标识符最多 32 字节（含 `#`）；流式遍历语句，避免先分配全文件的语句数组。
IFC 最多十万个根对象、两百万次逆关系访问；引用规范化最多十万次调用、累计扫描 256 MiB、累计写入 64 MiB，
中间递归结果、父级副本和属性键均计费，缺失引用也计入逆关系预算。耗尽预算立即报错，不返回部分比较结果。
DXF 最多十万条记录、两百万组码；展开块引用前预留最多十万个图元/访问项和
两百万组码的遍历预算，重复引用和父 INSERT 查询重复计费，折线按顶点数保守预留线段。
DXF 比较签名与渲染输出分别按保守估计的 256 MiB、128 MiB 预算预留，包含
图层、公共字段和 MTEXT 的字符串转义扩张，避免先构造巨大结果再检查。
超限候选返回 422；已上传但超限的模型可能无法比较或生成预览，需要拆分或简化。

任务名额限制并发数量，不代表总内存配额。比较仍读取两个完整产品，原始输入受字节预算约束；
下载使用[私有文件快照](/architecture/previews)。Go 堆之外还应考虑 Python/Node 原生内存与 PostgreSQL。
容量规划应使用实际模型大小、并发数与慢客户端测试，见[性能验证](/operations/performance)。

## 当前恢复范围

数据库事务、提交凭据与投影 journal 保护已提交状态。普通同步请求不自动续跑；
显式工作流将固定源码、输入、环境摘要及阶段检查点保存到 PostgreSQL。
扫描器重新领取过期尝试；沙箱执行不持数据库连接。候选与阶段同事务提交，
模型版本发布与工作流 publication 标记也共享一个事务和提交凭据。
转换队列仍在进程内去重；持久 conversion 阶段会检查已发布身份，并重建丢失的入队通知。
不保存 Python 进程内存或堆栈。恢复、取消与限额详见[工作流 API](/reference/workflows)。
